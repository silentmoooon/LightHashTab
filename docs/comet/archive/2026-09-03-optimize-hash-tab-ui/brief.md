# 目标

优化 LightHashTab 在 Windows 属性页中的显示效果：
1. 解决高 DPI 缩放下表头（如 `Algorit...`）和算法名称（`SHA-2...`、`SHA-5...`）以及按钮文字（`Select Al`、`Cance`）截断问题。
2. 规范化“算法设置”窗口：修复缺失标题栏和边框的样式缺陷，改造为居中弹出的标准模态对话框，采用规整的两列排版与宽裕的边距。
3. 改进字体与长哈希显示：等宽字体（Cascadia Mono / Consolas）随系统 DPI 等比缩放，Hash 列支持宽度自适应与横向滚动，添加列表 Tooltip 悬停显示完整哈希。
4. 增强哈希比对与匹配视觉反馈：匹配时整行柔和绿色背景高亮，状态文字清晰醒目。
5. 全面中文化：将界面控件、表头、按钮及提示文字转换为规范流畅的中文。

# 非目标

- 不改变底层哈希流式计算逻辑及硬件加速算法实现。
- 不变更 COM 接口协议与 Shell 属性页集成方式。
- 不引入外部庞大的 UI 框架，保持纯 Win32 API + NativeAOT 极小体积和超高启动性能。

# 验收示例

- A1: 主属性页在高 DPI 缩放下控件与文字无截断。用户在任意 DPI 缩放比例（100%、125%、150% 等）下打开文件属性的“文件哈希”属性页时，表头“算法”、“哈希值”完整展示无省略号，算法名称完整显示，底部操作按钮（“设置”、“复制”、“复制全部”、“粘贴/清除”）具有合适内外边距且文字完整显示。
- A2: 算法与哈希列表展示支持完整自适应与等宽字体清晰显示。哈希值使用清晰易读的等宽字体呈现且字体高度随 DPI 协调缩放；当哈希值超出显示区域（如 SHA-512 128位）时允许横向滚动查看完整内容，且鼠标悬停在列表项上时弹出 Tooltip 显示完整哈希值。
- A3: 算法设置对话框具备正规标题栏、关闭按钮、两列排版且按钮无截断。用户点击“设置”按钮打开算法配置窗口时，弹出窗口位于父窗口中央，具有标准标题栏（“算法设置”）、系统边框与关闭按钮；算法复选框采用双列整洁对齐排版，底部 [全选] [默认] 与 [确定] [取消] 按钮文字完整、间距舒适。
- A4: 哈希比对与匹配状态具备清晰反馈与整行高亮。用户在比对框中输入或粘贴与某算法匹配的哈希字符串时，列表对应行以浅绿底色整行高亮显示，状态提示清晰显示“✔ 匹配成功: <算法名>”；当输入 8 位以上不匹配内容时显示“✖ 未匹配”。
- A5: 界面文案与提示信息规范中文呈现。属性页标题为“文件哈希”，比较提示为“比对:”，快捷操作菜单与状态反馈均为规范中文。

# 约束与不变量

- 保持 .NET NativeAOT 编译无警告、无运行时反射依赖，产物保持轻量独立 DLL。
- Win32 GDI 资源（HDC、HFONT、HBRUSH、HICON 等）必须配对释放，避免内存或 GDI 句柄泄漏。
- 保证在 Windows 10 与 Windows 11 下的浅色和暗色主题下均具有良好的视觉可读性与对比度。

# 决策

- 决策 1：界面语言全面本地化为中文，兼顾专业习惯（如算法名保留标准大写缩写 BLAKE3、SHA-256 等，功能按钮与状态显示使用简体中文）。
- 决策 2：建立基于 `GetDpiForWindow` 的 DPI 动态缩放辅助计算，所有坐标、边距、按钮尺寸、表头宽度及字体高度全部应用 DPI 缩放因子。
- 决策 3：算法设置窗口重构为标准弹窗模态样式（移除错误的 `DS_CONTROL`），增加居中逻辑，算法复选框采用两列流式排版，底部操作按钮分组排布。
- 决策 4：等宽字体根据系统字号按比例生成，Hash 列根据内容计算合理宽度，启用 ListView 悬停提示 Tooltip。
